# CLI-Anything 案例与适用场景

## 官方案例能证明什么

| 案例类型 | 项目展示的能力 | 可证明 | 不能证明 |
|---|---|---|---|
| Blender / FreeCAD | 通过真实应用后端操作工程并渲染/导出 | 可把复杂桌面软件能力暴露成结构化命令和制品 | 主观设计质量、企业生产稳定性 |
| Slay the Spire II | 读取状态并执行连续动作 | 显式状态和会话比纯坐标点击更适合 Agent | 与 CI/CD 任务的直接效果 |
| 多类 Harness Catalog | 同一 SOP 适配不同软件 | 方法具有一定广度 | 每个 Harness 同等完整、安全或可维护 |
| Preview integrations | 生成 manifest、summary、artifact 等反馈包 | 结果可被 Agent/人共同检查 | 所有应用都已具备真实 Preview、结果一定正确 |

## CI/CD 实践案例设计

### 案例 A：内部构建诊断器

将只有 GUI/内部库的依赖图和失败诊断能力生成只读 CLI：`inspect-config`、`dependency-graph`、`explain-failure`、`export-evidence`。在隔离 Runner 内由 Agent 调用，最终只生成诊断与 Draft PR。

**验收：** 固定失败集归因准确率、首次命令成功、无效调用、产物完整率、人工修改和每成功修复成本。

### 案例 B：制品元数据与验证工具

先生成查询版本、SBOM、签名和依赖关系的 Observe Toolset；写 Toolset 只允许上传测试仓候选制品，且需 dry-run、幂等键和制品哈希。生产签名、晋级、删除不进入默认接口。

**验收：** 目标仓误选率、重复上传、签名验证一致性、权限拦截和审计完整率。

### 案例 C：发布后诊断导出

把传统运维桌面工具的状态查询、历史导出和诊断包生成暴露成 CLI，不开放恢复动作。Agent 在事故回放环境收集证据并生成时间线。

**验收：** 证据覆盖、时间线准确、缺失/污染、调查耗时和人工接管。

### 案例 D：专业测试或仿真软件进入 Pipeline

对有源码/脚本 API 的桌面测试工具生成项目创建、参数配置、运行、结果导出 CLI，以真实报告和产物作为 Oracle。先用于非生产构建验证。

**验收：** 项目状态持久化、运行可重放、结果包一致性、许可证/并发和 Runner 成本。

## 适合度矩阵

| 条件 | 高适合 | 低适合 |
|---|---|---|
| 可访问性 | 开源或企业可访问源码/后端 API | 闭源黑盒、只有屏幕 |
| 任务性质 | 结构化动作、可导出产物、可编程验证 | 强主观视觉判断、自由交互 |
| 风险 | 只读、沙箱、Draft PR、非生产 | 生产发布、删除、签名、不可逆动作 |
| 频率 | 高频长尾、人工包装成本高 | 一次性低频任务 |
| 维护 | 有 Owner、测试集和版本策略 | 无人维护、后端快速漂移 |
| 数据 | 可在批准模型/环境分析 | 代码/数据禁止向生成模型暴露 |
