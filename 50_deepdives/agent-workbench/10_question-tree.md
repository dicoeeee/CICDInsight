# Agent 工作台产品功能问题树

## Q0：产品边界和状态是什么？

- 产品名称、产品面和面向的使用者是什么？
- 产品整体与单项能力分别处于什么生命周期？
- 哪些页面只描述能力存在，未声明 GA/Preview/Beta？
- 相邻产品之间哪些上下文、权限或治理能力不能互相补全？

## Q1：用户从哪里开始任务？

- 入口位于桌面、Web、移动端、CLI、IDE、仓库、Pipeline 还是 Runbook？
- 用户提交的是自由目标、结构化输入、Issue、代码仓、Pipeline 变量还是前序日志？
- 是否存在本地与云端、交互与后台、UI 与 IDE 等不同执行面？

## Q2：任务和上下文怎样组织？

- 配置对象是 Project、Task、Chat、Agent、Expert、Flow、Workflow 还是 Pipeline Step？
- 项目指令、文件、知识源、仓库、Memory、变量和连接器如何被任务使用？
- 官方公开了哪些任务状态、暂停/继续、失败、归档和任务隔离行为？
- 定时、事件和手动触发分别如何配置？

## Q3：Agent 如何协作和扩展？

- 是否支持专家团、Subagent、Custom Flow、多 Agent 委派或顺序 Pipeline 串接？
- 谁拆解任务、如何汇总结果，官方公开了哪些执行细节？
- Skill、Plugin、MCP、Connector、CLI、Tool、Engine 分别是什么配置对象？
- 这些扩展如何安装、启用、版本化、过滤或撤销？

## Q4：产物如何呈现和交接？

- 产物是文件、文件变更、预览、报告、变量、Issue、评论还是 PR？
- 用户能否查看中间步骤、差异、运行日志、Token 或成本？
- 输出如何传给后续 Pipeline condition、approval、notification 或仓库规则？
- 哪些产物只是候选结果，不能代表测试、合并或发布已经通过？

## Q5：身份、权限和治理如何实现？

- 任务使用最终用户身份、服务账号、复合身份、短期凭据还是独立 Agent 身份？
- 文件、命令、网络、工具和连接器访问如何限制？
- 管理员能否控制 Agent/专家版本、可见范围、连接器、模型、工具、发布和分享？
- 有哪些审计、Trace、运行日志、合规、评测或成本记录？
- 哪些批准发生在 Agent 外部的 CI/CD、仓库 Ruleset 或环境控制面？

## Q6：官方没有证明什么？

- 多 Agent 是否提升质量、速度或成功率？若无官方可复验数据，保持未验证。
- 工作台是否原生支持 CI/CD 发布？只有直接产品功能才可写入。
- 生成 Issue、PR、变量或建议是否自动触发并通过后续 Gate？依赖配置的行为保持条件化表述。
- 单一产品整体 GA 是否覆盖所有子能力？逐项核验，不能继承。

## 结论门禁

只有同时满足以下条件的内容才进入报告正文：

1. 具名产品与功能对象明确；
2. 官方来源可访问并能直接证明表述；
3. 页面日期、产品状态或“未声明”已经记录；
4. 输入、输出、权限和限制没有跨产品补全；
5. 表述不包含产品事实之外的企业方案或采购评价。
