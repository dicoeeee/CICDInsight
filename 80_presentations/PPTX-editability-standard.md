# PPTX 原生可编辑性与交付验收规范

> [!important] 核心要求
> 后续生成的 PPTX 必须是可以在 Microsoft PowerPoint 中继续设计的源文件，而不只是“看起来像 PPT”的渲染结果。由我们生成的文本、框、表格、图表和连线应保持原生可编辑；用户必须能够修改字体颜色、移动和调整对象，并自由组合或取消组合。

## 一、适用范围

本规范适用于 `outputs/` 中交付的所有 `.pptx` 成品，包括公司洞察页、能力页、专题汇报和完整 Deck。

外部截图、照片、厂商界面截图和无法合理矢量化的证据图片可以继续作为图片使用；除此之外，不得把页面主体、架构图或整页内容栅格化后伪装成“可编辑 PPT”。

## 二、“可编辑”的最低定义

### 1. 文本必须可编辑

- 标题、正文、标注和页脚必须是原生 PowerPoint 文本对象，并包含真实文本内容。
- 文本不得转换为图片、SVG 路径、EMF 轮廓或其他不可直接编辑的图形。
- 用户选中文本或文本框后，必须能够修改字体、字号、字重和字体颜色。
- 文本对象不得包含 `noTextEdit` 或 `noSelect` 等编辑锁。
- 默认中文字体使用微软雅黑；如项目另有模板，以模板字体为准。

### 2. 对象必须可组合

- 用户在同一页选中两个或多个对象后，必须能够执行“组合”，并能够再次“取消组合”。
- 需要共同编辑的对象必须位于幻灯片画布中，不能分别固化在 Master、Layout 和 Slide 三个不同层级。
- 用户可编辑对象不得包含 DrawingML `noGrp="1"`。
- 不得因为生成工具的默认保护设置而禁用组合。

### 3. 图形必须保持原生

- 框、圆角矩形、线条、分隔线和简单架构图使用 PowerPoint 原生 Shape。
- 表格优先使用原生 Table，数据图优先使用原生 Chart。
- 页面主体不得合并为一张整页 PNG。
- 每个对象应能单独选择、移动、缩放和修改颜色。

### 4. 分组应服务于后续设计

- 交付文件可以预先组合语义上稳定的局部模块，例如“层级外框 + 层标题 + 层内说明”。
- 预分组不是强制要求；但即使未预分组，用户也必须可以自行组合。
- 不把整页锁成一个大组，不用组合掩盖重叠、错位或图层混乱。

## 三、生成与兼容性要求

1. 生成工具输出“原生 Shape”不等于最终文件一定可组合，必须检查最终 PPTX，而不是只检查生成代码或中间对象模型。
2. 如果生成工具在 Shape 上写入 `noGrp="1"`，该文件不得作为最终成品交付。
3. 出现生成工具兼容性问题时，应通过标准 PowerPoint/Office 兼容的重新保存或导出流程进行规范化，再重新验收。
4. 不直接用字符串替换方式修改 PPTX 内部 XML 作为正式生产方案，避免损坏关系、主题、批注或对象 ID。
5. 兼容性处理后必须重新检查内容、排版、字体、对象数量、编辑锁和渲染结果。

> [!bug] 已知问题记录
> 2026-07-24 的 Harness 单页中，生成结果为 56 个原生 Shape，但每个 Shape 都被写入 `noGrp="1"`，因此 PowerPoint 的“组合”不可用。后续不能再仅凭“对象是 Shape”判断文件可编辑，必须把组合锁检查加入交付门禁。

## 四、交付前自动检查

最终文件至少通过以下检查：

| 检查项 | 通过标准 |
|---|---|
| PPTX 文件完整性 | Office Open XML 压缩包结构完整，可以正常打开 |
| 页面渲染 | 所有页面可渲染，无缺字、错位、裁切和异常换行 |
| 页面越界 | 没有对象超出画布，没有非预期重叠 |
| 原生对象 | 页面主体由 Shape、Text、Table、Chart 等原生对象组成 |
| 整页图片化 | 不存在覆盖整页的单张图片，除非用户明确要求 |
| 组合锁 | `noGrp="1"` 数量必须为 `0` |
| 文本编辑锁 | `noTextEdit="1"` 和 `noSelect="1"` 数量必须为 `0` |
| 文本对象 | 标题、正文和标注具有真实文本内容与 `txBody` |
| 字体 | 中文字体符合模板要求；无模板时使用微软雅黑 |
| 来源与备注 | 外部事实和素材的来源记录得到保留 |

自动检查必须针对最终交付文件运行。中间版本通过不能替代最终文件通过。

## 五、PowerPoint 人工抽检

如果当前环境可以使用 Microsoft PowerPoint，交付前至少完成一次抽检：

1. 任意选择两个框或“框 + 文本”，执行组合；
2. 取消组合，确认对象仍可分别选择；
3. 选择一个文本框，将字体颜色改为明显不同的颜色；
4. 修改一个文本框的字号或字体；
5. 保存、关闭并重新打开文件，确认修改仍然存在；
6. 撤销测试修改或在副本中完成抽检，避免污染最终版。

如果环境没有 PowerPoint，必须明确记录该限制，并以 OOXML 编辑锁检查、原生对象检查、兼容性重新保存和完整渲染作为替代门禁。

## 六、归档规则

- 评审阶段可以使用带版本号或 `powerpoint-editable` 后缀的副本。
- 用户确认后，将通过验收的版本归档为项目约定的规范文件名。
- 规范文件名只保留一个当前版本，避免 `final`、`final2`、`v3` 长期并存。
- Presentation 页面中的“可编辑成品”链接必须指向最终规范文件。
- 提交前只暂存本次 PPTX 及其直接相关文档，不混入 Obsidian 工作区状态或其他页面资产。

## 七、完成定义

只有同时满足以下条件，才能向用户声明“所有元素可编辑”：

- 页面主体没有图片化；
- 文本颜色和字体能够修改；
- 对象能够自由组合和取消组合；
- 没有组合、选择或文本编辑锁；
- 排版渲染与内容版本一致；
- 最终文件通过自动检查，并在条件允许时完成 PowerPoint 人工抽检。
